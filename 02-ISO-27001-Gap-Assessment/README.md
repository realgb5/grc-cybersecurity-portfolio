# ISO/IEC 27001:2022 Gap Assessment

## Overview

A simulated ISO/IEC 27001:2022 gap assessment for a fictional financial services organization.

The project demonstrates how a GRC / IT Risk professional can evaluate an organization's information security management practices against selected ISO 27001 requirements and representative Annex A controls.

> **Disclaimer:** This is a simulated portfolio project. The organization, assessment data, evidence, findings, risks, and recommendations are fictional and created for demonstration purposes. This is not a certification audit and does not claim ISO/IEC 27001 conformity or certification.

---

## Project Objectives

- Assess information security management practices
- Identify gaps against selected ISO 27001 requirements
- Evaluate representative Annex A controls
- Identify and prioritize information-security risks
- Develop remediation recommendations
- Create a Statement of Applicability summary
- Develop an executive-level remediation roadmap

---

**ISO/IEC 27001:2022**

## Assessment Methodology

The assessment followed a simplified GRC gap-assessment workflow:

**Requirement / Control → Applicability → Current State → Target State → Gap → Risk → Recommendation → Remediation**

Each selected requirement or control was evaluated using:

- Applicability
- Current implementation state
- Target state
- Gap identification
- Priority
- Evidence / rationale
- Recommended remediation
- Control owner

---

## Key Findings

The simulated assessment identified several areas requiring remediation:

| Risk Area | Priority | Example Finding |
|---|---|---|
| Identity & Access Management | Critical | Inconsistent identity lifecycle and access-control practices |
| Risk Management | Critical | Inconsistent information-security risk treatment documentation |
| Authentication | Critical | MFA coverage and exception governance require improvement |
| Vulnerability Management | High | Remediation SLAs and exception tracking require strengthening |
| Supplier Security | High | Security requirements vary by supplier risk tier |
| Logging & Monitoring | High | Logging coverage and retention are inconsistent |
| Internal Audit | High | Formal ISMS internal-audit program is not established |

---

## Risk Assessment

A **5x5 likelihood and impact model** was used to prioritize simulated risks.

**Risk Score = Likelihood × Impact**

Risk ratings include:

- Critical
- High
- Medium
- Low

> The 5x5 scoring model is a portfolio methodology used for this simulation and is **not prescribed by ISO/IEC 27001:2022**.

## Remediation Roadmap

### 0–90 Days

- Strengthen identity lifecycle controls
- Formalize information-security risk assessment and treatment
- Establish clearer ISMS governance and accountability

### 31–120 Days

- Implement vulnerability remediation SLAs
- Strengthen supplier security requirements
- Improve logging standards and monitoring coverage

### 61–120 Days

- Establish an ISMS internal-audit program
- Track continual-improvement activities
- Strengthen management-review evidence
